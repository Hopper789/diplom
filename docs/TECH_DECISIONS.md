# Обоснование технических решений

## Почему BOINC

BOINC уже содержит модель `project/workunit/result/host`, scheduler, загрузку входных файлов и возврат результатов. Он подходит для независимых задач, где одну большую работу можно разбить на много маленьких workunits.

Также BOINC поддерживает параметры надёжности: `target_nresults`, `min_quorum`, `max_error_results`.

## Почему Docker

Docker даёт воспроизводимую среду для сервера и клиентов. Проще чистить runtime, переносить стенд и изолировать зависимости, чем настраивать нативный BOINC client вручную на каждом узле.

## Почему Ansible

Ansible управляет узлами по SSH и не требует агента. В проекте он устанавливает Docker, запускает клиентские контейнеры и разворачивает агенты мониторинга.

## Почему Ansible Vault

Sudo-пароль клиентов не должен лежать открытым текстом. Vault хранит его зашифрованным, а `ansible/.vault_pass` позволяет скриптам запускаться без повторного ручного ввода пароля. Оба файла считаются локальными для стенда и не коммитятся.

## Разделение подготовки и запуска

Подготовка системы и запуск кластера разделены на два этапа:

- `prepare_system.sh` — проверяет и подготавливает машины;
- `launch_cluster.sh` — запускает BOINC-инфраструктуру.

`quickstart.sh` оставлен как единая команда для полного запуска.

Такой подход позволяет:

- запускать весь стенд одной командой;
- отдельно проверять окружение;
- повторно запускать кластер без повторной настройки SSH/Vault;
- использовать отдельные скрипты для отладки.

## Почему Prometheus и Grafana

Prometheus хорошо хранит временные ряды, а Grafana удобно показывает прогресс эксперимента, BOINC-метрики и нагрузку CPU/RAM/network клиентов.

## Почему Python и Numba для задач

Основной пользовательский формат задач — Python. Он проще для быстрой разработки и хорошо подходит для независимых parameter sweep, симуляций и обработки данных.

Для ускорения CPU-кода клиентский образ включает `numpy` и `numba`. Это позволяет писать вычислительные ядра на Python и компилировать горячие циклы без отдельной сборки низкоуровневого приложения внутри BOINC server.

## Почему JSON input/output

JSON удобен для Python-задач и будущих GPU-задач. Его легко генерировать, читать, валидировать и архивировать вместе с результатами эксперимента.

## Почему Telegram notifier

Долгие эксперименты не хочется проверять вручную каждые несколько минут. Telegram-уведомление о завершении даёт простой канал обратной связи без полноценной системы alert manager.

## Ограничения

- BOINC эффективен для независимых задач.
- Очень короткие задачи могут проигрывать из-за накладных расходов scheduler.
- GPU требует отдельной настройки контейнеров, рантайма и маршрутизации задач.
- Telegram notifier будет базовым и не заменяет полноценный alert manager.
