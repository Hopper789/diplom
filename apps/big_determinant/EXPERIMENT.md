# regularized log-det

CPU-задача для BOINC Python runner: regularized log-determinant benchmark.

Каждая workunit:

- генерирует плотную квадратную матрицу по `seed`;
- последовательно считает `numpy.linalg.slogdet` для `A + lambda I`;
- возвращает параметры выданной задачи, сетку регуляризации, выбранную
  регуляризацию, `log_abs` и время выполнения для каждой точки.

Искусственной длительности нет: задача завершается после вычисления своего
пути регуляризации. Максимальный срок возврата результата задаётся
BOINC-параметром `DISTRIBUTED_DELAY_BOUND`; по умолчанию это `86400` секунд,
то есть 1 день.

Сложность регулируется размером матрицы `MATRIX_SIZE` и количеством значений
`REGULARIZATION_LAMBDAS` в `apps/big_determinant/main.py`. Для плотной матрицы
одна факторизация растёт примерно как `MATRIX_SIZE^3`, память — как
`MATRIX_SIZE^2`; общее время почти линейно растёт от числа `lambda`.

Если текущий размер `N` даёт время `T`, то новый размер для целевого времени
`T_target` можно оценить так:

```text
N_new = N * (T_target / T)^(1/3)
```

Ручной запуск через BOINC:

```bash
apps/big_determinant/run_task.sh boinc
```

Запуск через общий runner:

```bash
./scripts/run_experiment.sh --task determinant
```

У задачи нет внешних параметров сложности: размер матрицы, сетка регуляризации
и стратегия дробления на workunit заданы в `apps/big_determinant/main.py`.

Текущая стратегия:

- `MATRIX_SIZE = 8000`;
- `REGULARIZATION_LAMBDAS` содержит 16 значений;
- `WORKUNITS = 20`.

Будет создано 20 workunit независимо от числа клиентов. BOINC раздаёт их
клиентам динамически, поэтому быстрые узлы могут забрать больше задач, а
медленные не останавливают общий прогресс.
